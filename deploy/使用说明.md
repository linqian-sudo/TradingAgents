# TradingAgents 研究入口使用说明

本说明面向共享 Linux 上的「AI股神团队」研究助手。安装包来自发行 bundle，不需要克隆仓库。这里只做个股研究调用：不连接券商，不下单，不读取持仓或资产，不发送飞书，不启用异动监控或定时任务，不监听公网端口。

上游是 Tauric Research 的 TradingAgents **0.7.1**，commit `9fa1196fffbcfd9de5146d2dd2869df84ab99838`，许可证 Apache-2.0。研究封装在此之上，不替换该许可证。

## 安装

```bash
tar -xzf tradingagents-research-0.7.1-9fa1196.tar.gz
cd <解压目录>
./deploy/install.sh --prefix "$HOME/.local/share/tradingagents-research"
./deploy/self_check.sh "$HOME/.local/share/tradingagents-research"
```

共享目录可改为团队账号可写的路径，例如 `--prefix /opt/tradingagents-research`。安装只创建该前缀下的 venv，不使用系统 Python 的全局 site-packages。

`install.sh` 默认按 `deploy/requirements.lock.txt` 安装依赖，再安装本目录里的本地包，避免从 PyPI 拉一个同名的上游发行版把研究入口盖掉。锁文件缺失时脚本会失败，不会自动改成浮动版本。只有在明确接受版本漂移时才加 `--unpinned`。

需要 Python 3.11 或更新。本包在云 VM 的 CPython 3.12.3、linux x86_64 上安装并自检过。其他系统要重新执行安装；锁文件里的轮子不一定覆盖非 Linux 平台。

## 调用

把下面的 `BIN` 换成安装前缀里的 `bin/tradingagents-research`。

```bash
BIN="$HOME/.local/share/tradingagents-research/bin/tradingagents-research"
OUT=/tmp/ta-research
```

符号核对（不访问网络，不产生行情，不判断代码是否存在）：

```bash
"$BIN" map --reference --output "$OUT/map"
```

对照代码是公开示例：`0700.HK`、`1810.HK`、`601398.SS`、`002779.SZ`、`688825.SS`。`700.HK` 与 `00700.HK` 会规范成 `0700.HK`；`601398.SH` 会规范成 `601398.SS`。深圳代码保持 6 位，例如 `002779.SZ` 不会被改成别的后缀。`688825` 使用上交所后缀 `.SS`。映射结果里的 `exists` 和 `quote` 固定为空。

只读公开日线（Yahoo Finance，经项目自带的 yfinance；不更换数据源）：

```bash
"$BIN" data-check --symbol 0700.HK --market HK --date 2026-11-06 --output "$OUT/tencent"
```

`--market` 取 `HK`、`SS`、`SH`、`SZ` 或 `US`。`SH` 表示上交所，规范化后缀是 `.SS`。后缀与市场不一致时不会发请求。退出码：`0` 表示返回了日线；`4` 表示源站没有该窗口的数据；`3` 表示网络、权限或频率限制，错误原样写入 `status.json`。这只说明公开历史数据是否可读，不是研究报告，也不保证实时或完整财报。

研究运行：

```bash
"$BIN" run \
  --symbol 0700.HK --market HK --date 2026-11-06 \
  --output "$OUT/run" \
  --provider ollama \
  --quick-model <已在本地提供的模型名> \
  --deep-model <已在本地提供的模型名> \
  --analysts market
```

未指定 provider，或托管 provider 缺少对应 API Key 时，命令退出码为 `2`，`status.json` 里 `model.status` 为 `model_unconfigured`，`research.end_to_end` 为 false。此时不会构造模型客户端。不要把这个结果或行情连通性结果说成端到端研究成功。

每次命令都写：

- `status.json`：结构化状态
- `summary.zh.md`：中文概要，数字只来自同一次状态

输出目录由调用方指定。安装器另外把上游 CLI 的默认结果目录指到前缀下的 `var/`，避免写到个人主目录的 `~/.tradingagents`。

## 模型与费用

本入口不代选付费方案。默认轮数、token 和超时是调用上限，可以改，但改大之前需要操作者自己向服务商确认价格。本包装阶段没有模型 API Key，验证时没有发起模型调用，因此不能给出单次费用。

最少需要：

- 显式 `--provider`（或环境变量 `TRADINGAGENTS_LLM_PROVIDER`）
- 显式 quick 与 deep 模型名
- 托管服务：该 provider 的一个 API Key 变量
- `openai_compatible`：还要 `TRADINGAGENTS_LLM_BACKEND_URL` 或 `--backend-url`；Key 仅在端点要求时才需要
- `ollama`：不需要 Key；可选 `OLLAMA_BASE_URL`，否则上游默认 `http://localhost:11434/v1`

低成本或本地路径（是否真正低成本取决于操作者自己的机器和账户，这里不承诺）：

| 路径 | 额外变量 |
| --- | --- |
| `ollama` | 无 Key。本安装不启动 Ollama，也不拉取模型。 |
| `openai_compatible` | 端点 URL；可选 `OPENAI_COMPATIBLE_API_KEY`。可用于 vLLM、LM Studio、llama.cpp。 |

托管 provider 与变量名（只填被选中的那一个）：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY`、`DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`、`DASHSCOPE_CN_API_KEY`、`ZHIPU_API_KEY`、`ZHIPU_CN_API_KEY`、`MINIMAX_API_KEY`、`MINIMAX_CN_API_KEY`、`OPENROUTER_API_KEY`、`GROQ_API_KEY`、`MOONSHOT_API_KEY`、`MISTRAL_API_KEY`、`NVIDIA_API_KEY`、`XAI_API_KEY`、`AZURE_OPENAI_API_KEY`。

`chatgpt` 与 `bedrock` 在本入口中拒绝：前者要交互登录，后者要 AWS 凭证链。两者都不会在这里读取或使用。

行情连通性测试不需要模型 Key，也不需要 `FRED_API_KEY`。若以后把 `--analysts` 扩到 `news`，宏观工具仍指向 FRED；没有 Key 时上游会把该可选数据标为不可用，而不是编造数字。默认分析员只有 `market`。

研究入口的默认上限：辩论 1 轮，风险讨论 1 轮，工具轮数 8，输出 token 4096，请求超时 120 秒，SDK 重试 2 次。对应参数是 `--max-debate-rounds`、`--max-risk-rounds`、`--max-tool-rounds`、`--max-tokens`、`--timeout`、`--max-retries`。

示例环境文件是 `deploy/config.example.env`，里面没有密钥。填好的副本放在安装目录之外，不要放进公开仓库。

## 预算

DeepSeek 运行必须带总预算。价格卡来自 2026-11-08 再次核对的官方中文价格页，2026-11-15 00:00 UTC 前有效，过期就拒绝发送。预留只用人民币高峰价，输入按缓存未命中。官方写明价格可能变化，这套限额不能代替账单。

完整研究不再按 100 万上下文预留。每次发送前测量该次请求的 UTF-8 输入上界；超限时先保留工具结果的开头标识和结尾最近记录，并写明已截断。压不进去就拒绝发送。默认两个层级都是 `deepseek-flash`，分析员为 market、news、fundamentals，工具轮数 1，辩论和风险各 1 轮。结构化角色失败后不再自动发第二次自由文本请求。情绪分析员不进入这次预算运行。当前计划是 14 个槽。

此前输出上限 1024 时，有 7 次响应的 `finish_reason=length`，角色文本被截断，不能当作完整分析。建议输出上限改为 4096：单次输出预留从 0.008192 元增到 0.032768 元。14 个槽、输入上界 24000 时，最坏预留是 1.130752 元。下一次运行的 prior 用 1.959598 元（两份旧计划预留、基础预留 0.008448 和已知用量 0.040622）。合计约 3.090350 元，仍低于 9.5 元。4096 只是减少截断，不保证报告完整。`finish_reason=length` 的结果会标成未完成。

usage 缺失或进程中断留下的 `sending` 会冻结后续请求。未知费用按该槽上界保留，不能记为 0。已有账本不要删除。

发出前，请求体必须带官方字段 `max_tokens`，并且 `thinking.type` 为 `disabled`。账本里写下 1024 不等于供应商收到了 1024。LangChain 会把 `max_tokens` 改名为 `max_completion_tokens`；研究入口会在真正调用前把官方字段写回去。写不进去就不发送。

如果响应里的 `completion_tokens` 仍大于该次 `max_tokens`，这一次的费用已经发生，软件不能撤回。账本冻结并停止后续请求。因此不能把 9.5 元说成绝对账单上限。`completion_tokens` 按单次响应记账；多次相加的用量不能再当成同一次。`reasoning_tokens` 只记录明细，不重复加进 `completion_tokens`。已经写出的账本文件不要删除或改小。

当前模型名只用 `deepseek-flash`（DeepSeek-V4.1-Flash-1017）和 `deepseek-v4-pro`（DeepSeek-V4-Pro-0813）。`deepseek-v4-flash`、`deepseek-chat`、`deepseek-reasoner` 会拒绝。只接受 `https://api.deepseek.com` 的 Chat Completions。思考模式不关闭、没有 `max_tokens`、重试不为 0、流式或非文本内容，都不会发送。

基础探测按高峰未命中价预先占用 0.000030 元（7 个输入 token、2 个输出 token）。父级看到的 0.000015 元是空闲时段估算，不是这套账本的占用。因此 1 元总预算的剩余可预留额度是 0.999970 元。

```bash
"$BIN" budget --output "$OUT/budget"
"$BIN" run --symbol 0700.HK --market HK --date 2026-11-06 --output "$OUT/tencent" \
  --provider deepseek --quick-model deepseek-flash --deep-model deepseek-flash \
  --analysts market,news,fundamentals --max-tool-rounds 1 --max-debate-rounds 1 \
  --max-risk-rounds 1 --max-tokens 4096 --max-retries 0 \
  --budget-cny 9.5 --prior-hold-cny 1.959598 --input-token-cap 24000 \
  --budget-mode research
```

父级有密钥之后才执行 `run`。云端验证只用 mock，不调用模型。示例变量在 `deploy/budget.example.env`，里面没有密钥。

## 结果怎么读

`research.end_to_end` 为 false 时，没有完成模型研判。`data.status` 为 `ok` 只表示 yfinance 返回了公开日线，来源主机是 Yahoo Finance 的查询主机，时间在 `fetched_at`。`no_data` 表示该窗口没有返回，价格字段保持空。`unavailable` 表示请求没有完成，原因写在 `error` 与 `cause`，不改用别的数据接口。

港股和 A 股能按上述后缀进入 Yahoo 路径，不表示盘中实时，也不表示财务报表完整。
