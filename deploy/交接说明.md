# AI股神团队交接说明

## 交付物是什么

父级拿到的是可安装 bundle，不是一份需要再克隆的 git 工作副本。解压后执行 `deploy/install.sh`。源代码、Apache-2.0 `LICENSE`、`NOTICE`、研究入口和部署脚本都在包内。包内没有 `.git`、没有 venv、没有 API Key。

公开 fork 只承载无密钥的封装与测试代码。真实测试日志、`status.json` 和本次云 VM 的验证记录放在 artifacts，不写入公开仓库。

## 已在云 VM 上核对的范围

- 上游版本固定为 TradingAgents 0.7.1，commit `9fa1196fffbcfd9de5146d2dd2869df84ab99838`，许可证 Apache-2.0。
- 依赖以 `pyproject.toml` 为准：LangChain / LangGraph、yfinance、pandas 等研究与数据读取库。依赖里没有券商下单 SDK。脚本与 compose 文件没有飞书发送、公网端口或 cron。
- 研究入口不读取持仓、不调用下单、不启动定时任务。模型客户端只在 provider、模型名和所需凭证都齐时才构造。
- 隔离 venv 中的安装、`import`、上游 CLI `--help` 与研究 CLI `--help` 由同一次云 VM 记录。记录在 artifacts 的日志和 `status.json`，不在这份仓库说明里宣称父级机器已经装好。

## 预算

总预算改为 9.5 元。完整研究按每次真实请求的输入上界预留，不再按 100 万上下文拒绝。默认全程 `deepseek-flash`，保留 market、news、fundamentals、多空研究、交易员、风险和组合经理。工具轮数降到 1，这是仍会调用工具的最小轮数，不是改成单次摘要。最坏 17 槽预留 0.955264 元，加上基础调用预留 0.008448 元，低于 9.5 元，所以允许尝试。请求无法压进上界时发送前拒绝，并在账本标明截断或未完成。不承诺一定跑完或与账单一致。

## 还不能当成已完成的部分

- 本阶段没有模型 API Key，验证不会发起收费或本地模型调用。`run` 在未配置时应退出码 2，状态为 `model_unconfigured`。这不是端到端研判。
- 单次费用取决于团队稍后选择的 provider、模型、轮数和输出长度。选择之前不能报价，本入口也不代选套餐。
- `0700.HK` 的只读日线是否成功，以 artifacts 里那次 `data-check` 的 `status.json` 为准。失败时保留源站错误，不换接口。
- `1810.HK`、`601398.SS`、`002779.SZ`、`688825.SS` 只做了符号规范化核对。映射成功不等于代码存在，也不附带行情。
- A 股与港股可以走 Yahoo 后缀，不保证实时，也不保证财报完整。默认基本面供应商在研究运行里设为 yfinance，而不是美股 SEC 文件。
- 父级共享 Linux 上的安装、团队账号权限，以及选定模型后的真实研判，都还没做。装好并选定模型后，用同一条 `run` 命令再测，并单独记录那次是否 `research.end_to_end=true`。

## 建议的团队用法

1. 在共享 Linux 上用新前缀安装，执行 `deploy/self_check.sh`。
2. 先跑 `map --reference` 和指定股票的 `data-check`，确认 `summary.zh.md` 里的来源与时间。
3. 团队选定本地 Ollama、兼容端点，或某一个托管 provider 后，只把对应变量注入运行环境，再执行 `run`。
4. 把每次 `status.json` 留在该次输出目录。不要把含密钥的环境文件或真实持仓放进仓库。

研究输出不是投资建议。无数据时状态保持 `no_data` 或 `unavailable`，助手不应补写价格或结论。
